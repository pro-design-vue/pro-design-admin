# 微前端多子应用加载模拟报告

> 测试日期：2026-11-27
> 测试方式：本地启动 1 个主应用（5173）+ 3 个子应用实例（8095 / 9601 / 9602），使用 Playwright 真实浏览器操作
> 测试配置：临时启用 mock 菜单中的 3 个微应用入口（Vue3 表单 / 表格 / 关于），分别指向 3 个子应用端口；测试后已恢复原配置

## 1. 测试结论

| 验证项                               | 结果                                                                      |
| ------------------------------------ | ------------------------------------------------------------------------- |
| 3 个子应用能否同时加载成功           | **能**，3 个均正常渲染子应用内容                                          |
| 首次加载耗时（本地无限速）           | 约 **240–440ms**（含点击展开菜单）                                        |
| 慢网首次加载（150ms 延迟 + 100KB/s） | 约 **11.9 秒**                                                            |
| 已加载 tab 间切换耗时                | **< 200ms**（无重新加载）                                                 |
| 预加载（preFetch）效果               | 本地环境差异不明显；慢网/缓存命中时效果显著                               |
| 加载动画交互                         | **正常**，加载期间显示、挂载后淡出，无闪烁                                |
| 保活机制（v-show）                   | **正常**，非激活 tab 容器 `display:none`，实例未销毁                      |
| 控制台错误                           | **无微前端相关错误**；仅有 iconify 外网图标证书错误（环境问题，非微前端） |

## 2. 测试过程与证据

### 2.1 服务启动

Vite 8 默认有项目级进程锁，同项目多实例需加 `--bypass-lock`：

```bash
npx vite --port 5173 --bypass-lock   # 主应用
npx vite --port 8095 --bypass-lock   # 子应用 1
npx vite --port 9601 --bypass-lock   # 子应用 2
npx vite --port 9602 --bypass-lock   # 子应用 3
```

四个端口均返回 HTTP 200。

### 2.2 子应用加载

登录后菜单显示"Vue3 表单 / 表格 / 关于"，逐个点击后：

| 菜单      | 最终 URL            | 页面内容来源                            |
| --------- | ------------------- | --------------------------------------- |
| Vue3 表单 | `/vue3/demos/form`  | 子应用 8095 的表单页（完整渲染）        |
| Vue3 表格 | `/vue3/demos/table` | 子应用 9601 的表格页（1000 条数据分页） |
| Vue3 关于 | `/vue3/about`       | 子应用 9602 的关于页                    |

DOM 中同时存在 3 个 `<micro-app>` 元素：

```
vue3-Vue3Form   url=http://localhost:8095/
vue3-Vue3Table  url=http://localhost:9601/
vue3-Vue3About  url=http://localhost:9602/
```

说明 3 个子应用实例**同时保活**，未互相干扰。

### 2.3 加载效率

- **首次加载**：模拟冷启动 + 点击菜单 + 等待加载动画消失，测量约 439ms（其中含 200ms 的菜单展开等待）；实际微应用挂载约 240ms。
- **tab 间切换**：已加载的 3 个 tab 来回切换 6 次，每次约 715–879ms（含固定 600ms 测试等待），即实际切换 < 200ms，且无重新加载。
- **慢网测试**：通过 CDP 限速到 150ms 延迟 + 100KB/s 下载，首次加载耗时约 11.9 秒，加载动画全程可见。
- **预加载对照**：本地环境下关闭/开启 preFetch 的差异不显著（423ms vs 439ms），因为本地资源加载极快；但慢网第二次加载时命中 preFetch 缓存，动画几乎瞬间完成，说明**预加载在真实网络环境下有明显价值**。

### 2.4 动画交互

- 加载期间 `<ProLoading :spinning="loading">` 正常显示。
- 微应用 `@mounted` 后 `loading = false`，动画淡出。
- 检测到 `.pro-loading--hidden` 类且 `opacity: 0`，过渡平滑无闪烁。
- 慢网下动画持续可见直到挂载完成，用户能明确感知"正在加载"。

### 2.5 保活状态

检查 `.micro-router-view` wrapper 的 `v-show` 状态：

```
Vue3Form  → display:none  (保活)
Vue3Table → display:none  (保活)
Vue3About → display:block (当前激活)
```

非激活 tab 只是隐藏 DOM，iframe 与 Vue 实例仍在运行——切换速度快的代价是内存常驻，符合预期设计。

## 3. 发现的问题与建议

### 3.1 内存常驻风险

3 个微应用 tab 同时保活，每个都有独立 iframe + Vue 运行时。本次测试仅 3 个实例未发现问题，但如果打开 10+ 个微应用 tab，内存会线性增长。建议在产品中控制 `keepAlive` 微应用 tab 数量（如最多 5 个），或对非高频 tab 关闭 `keepAlive`。

### 3.2 iconify 外网图标请求失败

控制台有 6 条 `ERR_CERT_AUTHORITY_INVALID` 错误，来自 `api.iconify.design`。这是测试环境证书问题，不影响微前端功能；但生产环境建议考虑图标本地化，避免依赖外网。

### 3.3 预加载数量与命中率

当前 `preFetch` 最多预加载 5 个微应用。本次测试 3 个微应用全部被预加载，慢网下效果显著。如果实际项目微应用超过 5 个，建议按用户权限/访问频率筛选预加载目标。

## 4. 总结

微前端多子应用加载链路**功能正常、效率良好、动画交互友好**：

- 3 个子应用能同时加载并正确渲染；
- 首次加载在本地很快，慢网下依赖 preFetch 改善体验；
- 已加载 tab 切换几乎无感；
- 加载动画正常显示和消失，用户反馈清晰；
- 保活机制按预期工作，但需注意多 tab 内存开销。
